# Sequencer, mapped state, slots, and timing

> Detailed evidence extracted from the original monolithic ARCHITECTURE.md.
> Ghidra is authoritative for current symbols, types, comments, and cross-references.

- `ProcessPeriodicTask` verifies that the running task is task ID 2, lazily
  allocates a 0x28-byte state object, and applies the same state-byte gate used
  by the other task entries. Its normal path initializes a periodic-service
  object, creates three 0x10-byte handler descriptors, and enters the
  non-returning dispatch loop at `0xC002A7AC`. That loop calls the scheduler/RTOS
  helper at `0xC00007AC` and then invokes a virtual method at object offset
  `+0x0C`. `RunPeriodicHandlerCountdown` (`0xC002A7EC`) decrements each
  descriptor's current countdown at `+0x04`, reloads it from `+0x08`, and invokes
  its callback at `+0x0C` on expiry. The five descriptors are at object offsets
  `+0x08`, `+0x0C`, `+0x14`, `+0x18`, and `+0x1C`; the first callback is
  `EmitCommonMessageType0` (`0xC00839C8`), and the second is
  `DispatchPeriodicLcdState3WhenEnabled` (`0xC002A71C`). When its singleton gate
  byte at `+0x04` is `1`, it tail-dispatches `LCD::DispatchLcdState` with state `3`
  and zero payload; dispatcher case `3` performs `RefreshLcdDisplay(lcd, 0)`. The
  final three callbacks are `0xC002A770`, `0xC002A734`, and `0xC002A730`.
  The object initialization also creates two 0x14-byte queue-like records and
  attaches a lazily allocated 0x1C-byte state object whose constructor obtains
  the AM1802 GPIO register block and a shared 0x118-byte subsystem object.
  `ProcessPeriodicServiceTick` (`0xC002A818-0xC002A8A3`) runs the descriptor countdowns and
  the shared periodic state updates. The `0xC002A730` thunk reaches
  `PollDspStatusAndEmitCommonMessage23` (`0xC004F20C`), which reads a 16-bit DSP
  status through host DMA; status `2` clears its gate, invokes the DSP-interface
  cleanup path, and emits common-message type `0x17` through
  `EmitCommonMessageType23` (`0xC0083C64`). The other two initialized callbacks
  only construct their singleton contexts and set a byte at `+0x04` to `1`; their
  higher-level roles remain unresolved.
- `CentralServiceTask::taskProc` verifies task ID 3, publishes service mode 1,
  and lazily constructs its 0x28-byte state object. On the normal state path it
  waits for RTOS object ID 2 using event mask `1`, then dispatches event bits:
  bit `0` drains the queue at `0xC002A590` and forwards each packet to
  `0xC0026288`; bit `1` drains the queue at `0xC002A594` into the singleton
  `PanelUartProtocolState` and forwards each packet to `0xC002814C`; and bit `2`
  obtains the SD-card driver and calls `0xC0083E7C` with its state byte at
  `+0x19`. A secondary path drains both queues regardless of which event bit
  was returned. The queue records are therefore distinct central-service
  work sources.
- `SeqTask::taskProc` (`0xC002AACC`, static task descriptor 10) calls
  `SeqTaskProcessCycle` (`0xC0057734`) once per loop after the device-status
  check and scheduler yield. That cycle reconciles 16 tracked state bits,
  runs sequencer/sound-engine helpers, drains the USB-MIDI and VoiceTask
  auxiliary queues through `DrainMidiInputQueuesToVoiceTask`, and then
  continues the sequencer state-machine update. The detailed meanings of its
  state fields are still unresolved.
- Sequencer state transitions also emit internal four-byte records directly
  through `QueueVoiceTaskEvent` (`0xC005A20C`) to the VoiceTask input queue at
  `0xC033E5A8`. The first packed byte is the caller's part/source value minus
  `0x80`; the other bytes are derived from the transition parameters and a
  handler-selected control value. This producer is distinct from the inbound
  MIDI auxiliary-queue path, while the precise record protocol remains
  unresolved.
 - `ProcessSeqTaskTransportCycle` (`0xC005F2E8-0xC005F5C3`) is the per-cycle
   transport state machine. It waits for the shared sample-pending byte to
   clear, handles transport states `1` and `2`, combines the position difference
   between `0xC068FC78`/`0xC068FC88` with pending elapsed state at
   `g_seqTransportElapsedPending` (`0xC068FC48`), and sends the resulting units
   to `ProcessSequencerTick`. Its interpolation branch advances a modulo-2000
   phase at `g_seqTimingInterpolationPhase` (`0xC0690DB4`), scales it to a
   `0..0x40` value at `g_seqTimingInterpolatedValue` (`0xC06900A5`), and publishes
   changes through `SetMappedStateValue`. It raises `g_seqTransportOverrunFlag`
   (`0xC069009C`) when the post-residual elapsed value exceeds `0x100` and writes
   a packed value into the 256-entry ring `g_aSeqTimingEventRing` using
   `g_seqTimingEventRingIndex`. The transport-state and mapped-state protocols
   remain unresolved.
 - `ProcessSequencerTick` (`0xC005E914`) consumes the elapsed units generated by
   that helper. It accumulates input at `0xC068FC70`, subtracts the quantum at
   `0xC06900A0` until below threshold, updates countdown/state counters, and
   iterates 32 records beginning at `0xC06904A8` with a `0x48`-byte stride.
   State changes dispatch to the surrounding sequencer/voice timing helpers.
   The record fields are not yet assigned product-level meanings.
   `g_bSeqTaskRecordsActive` (`0xC068FC6C`) is the shared activity gate for these
   records. `GetSeqTaskRecordWord8` (`0xC005D8A4`) returns indexed record word
   `+0x08` only while that gate is set, and `IsSeqTaskRecordsActive`
   (`0xC005D8F8`) exposes the gate directly. The field at `+0x08` remains
   semantically unresolved.
   `g_seqTaskTimingCountdown` (`0xC068FC80`) is the 0x60-unit countdown used by
   `ProcessSequencerTick`; `GetSeqTaskTimingElapsed` (`0xC005D8D0`) returns its
   complementary elapsed value (`0x60 - countdown`) while the record gate is
   active. `AllocateVoiceTaskSlotAssignmentRecord` uses the elapsed value against
   `0x30` to select immediate versus deferred assignment-record delivery. The
   higher-level musical meaning of this timing interval remains unresolved.
    `PrepareSeqTaskTimingTransition` (`0xC005C674`) moves a positive countdown to
    the observed `1`/`0x61` boundary sentinel and raises the cleanup-pending state
    during SeqTask setup. `ClearSeqTaskCleanupMarkerIfIdle` (`0xC005C894`) clears
   `g_seqTimingCleanupPending` (`0xC0690DC4`) only when the timing counter, a
   separate gate, and all 16 primary records are inactive. The separate gate and
   the related state flags remain semantically unresolved. `ResetSeqTaskRecordActivityAndFlushSlots`
   (`0xC005C8F0-0xC005C9AF`) clears the shared record-activity gate, deactivates the
   16 primary records, marks their cleanup bytes, resets associated VoiceTask
   part-slot work state, copies the timing/countdown fields, and forwards pending
   special-state 11/12 updates. `RefreshVoiceTaskSlotAssignmentTablesIfPending`
   (`0xC0057818-0xC005783B`) rebuilds the VoiceTask slot-assignment tables when
   its pending flag is set. The record-control and slot-assignment protocols
   remain unresolved.
   `EnterSeqTransportState1` (`0xC005D564`) and `EnterSeqTransportState2`
   (`0xC005D584`) publish transport states `1` and `2` with a value at
   `0xC068FC78`; `SetSeqTransportStateInactive` (`0xC005D5A4`) publishes `0xFF`,
   and `GetSeqTransportState` (`0xC005D5B8`) reads the state byte.
   `GetSeqTransportReferenceValue` (`0xC005DA34`) returns the comparison value at
   `0xC068FC88`, while `GetSeqTransportOverrunFlag` (`0xC005DA44`) returns the
   overrun latch. The transport values' higher-level units remain unresolved.
   `RefreshSeqTaskTimingPeriod` (`0xC005C6C4-0xC005C6E3`) reads shared
   VoiceTask control-object byte `+0x16` through `GetVoiceTaskControlField16`
   (`0xC0046B9C`) and selects `g_seqTaskTimingPeriod` (`0xC068FC40`) as `0x240`
   or `0x480`. The timing unit and control-field meaning remain unresolved.
    `ComputeSeqTaskTimingOffset` (`0xC005C6E8-0xC005C777`) gates on the two
    observed bytes at `0xC0690DB1`/`0xC0690DB8`, scales the current phase using
    `0xC068FC74`, divides by `g_seqTaskTimingPeriod`, and returns either the raw
    remainder or a further `0x60`-adjusted offset according to its selector. It is
    used by SeqTask timing-state setup and elapsed-position calculations; the
   timing unit and field meanings remain unresolved.
   `CalculateSeqTaskTimingTransition` (`0xC005D3FC-0xC005D553`) is the shared
   residual/interval helper called from SeqTask transport initialization and reset.
   Selector `1` accepts a residual below half the selected period, stores it in
   `g_seqTimingResidual` (`0xC0690DC8`), and returns the `0x60`-interval count plus
   one; otherwise it enters clock state `1`. Selector `2` incorporates
   `ComputeSeqTaskTimingOffset(0)`, either accepts the wrapped residual or enters
   clock state `2` and computes its countdown/remainder state. The interval unit
   and higher-level transition meanings remain unresolved.
   `HandleSeqTaskMidiRealtimeClock` (`0xC005E150-0xC005E233`) is called only by
   the MIDI parser's realtime-clock branch. It records the shared timer sample in
   `g_seqTimingClockSample` (`0xC068FC84`), raises `g_seqTimingClockSamplePending`
   (`0xC0690DC1`), and handles selector/state combinations while shared-system
   mode `g_sharedSystemObjectMode` (`0xC0690DB0`) is 2 or 3. A prior nonzero
   `g_seqTimingClockState` (`0xC0690DB8`) causes it to record
   `g_seqTimingClockDelta` (`0xC0690DBC`) as sample minus `g_seqTickQuantum`,
   raise `g_seqTimingClockDeltaPending` (`0xC068FC90`), and clear the state byte;
   selector 2 can also request `ComputeSeqTaskTimingOffset(1)`. The MIDI source
   categories, consumers, and product-level timing units remain unresolved.
   `ProcessMidiClockTransportState` (`0xC005E088-0xC005E133`) is the output-side
   companion called by `EmitMidiClockPositionUpdate` before it queues `FA`/`FB`.
   It runs only in shared-system-object mode `4`, consumes clock state `1` or `2`,
   and uses `g_seqTimingClockStateCountdown` (`0xC0690098`) to expire state `2`.
   When the state clears it records the input minus `g_seqTickQuantum` in
   `g_seqTimingClockDelta` and raises the delta-pending handshake; the emitted
   byte mapping is established by the caller, but the state meanings remain
   unresolved.
   `ResetSeqTaskTransportState` (`0xC005D5C8-0xC005D7E3`) is a separate reset
   routine previously swallowed by the oversized function beginning at
   `0xC002C4B0`. Its tail wrappers `RequestSeqTaskTransportResetMode1`
   (`0xC002C4B0-0xC002C4B7`) and `RequestSeqTaskTransportResetMode0`
   (`0xC002C4B8-0xC002C4BF`) pass the transition argument explicitly. The reset
   routine reactivates eligible primary records, runs the timing-transition and
   mode-specific clock-state branches, copies the observed timing phase/countdown
    fields, clears pending transport state, resets the part-slot tables, and may
    refresh the VoiceTask timing profile. The transition modes and individual timing
    fields remain unresolved.
   `UpdateSeqTaskTimingStateFromClock` (`0xC002C410-0xC002C46F`) is the timer-facing
   caller of `CalculateSeqTaskTimingTransition`. It masks interrupts, derives the
   elapsed difference from the shared timer object, passes the selected transition
   mode, and publishes a nonzero returned state into the timer object's `+0x0C`
   while clearing `+0x10`. The timer-object field meanings remain unresolved.
   `RefreshSeqTaskTickQuantumFromVoiceMode` (`0xC005D84C-0xC005D86F`) reads the
   VoiceTask control byte at `+0x2A`, stores it as `g_seqTimingModeIndex`
   (`0xC0690DA8`), and selects `g_seqTickQuantum` from
   `g_aSeqTickQuantumByMode` (`0xC00E2DDC`). The first four table entries are
   `6, 3, 8, 4`; the mode semantics and remaining entries remain unresolved.
   `UpdateSharedSystemObjectMode` (`0xC005E250-0xC005E293`) is the shared-mode
   transition helper used by the system-object mode paths. It normalizes input `1`
   to `0`, clears `g_seqTimingClockState` on entry to mode `0`, and primes
   `g_seqTaskTimingCountdown` to `1` for mode `4`; the shared-mode meanings remain
   unresolved.
   `GetSharedSystemObjectMode` (`0xC002B8F0-0xC002B90F`) is the common mode
   accessor used by the SeqTask transport gate, VoiceTask timer, startup, and
   shared-mode selection paths. It returns the raw mode except for raw mode `1`,
   which is remapped through the source object's `+0x10` selector and the table
   at `0xC00A4640` when that selector is below `3`.
   `MapSharedSystemObjectSelector` (`0xC002BDE4-0xC002BDFB`) is the shared
   selector-table helper. `ApplySharedSystemObjectRequestedMode`
   (`0xC002BE8C-0xC002BF63`) applies requested object modes `0`, `1`, `2`, and
   `0xFF`, updates the prior-mode byte, emits common-message type `15`, and
   republishes the derived mode. `GetSharedSystemObjectModeDependentValue`
    (`0xC002BF70-0xC002BFC3`) returns field `+0x14` from the selected mode object
    for resulting modes `2`, `3`, or `4`, otherwise `-1`; the field unit remains
    unresolved.
  - The shared-object lifecycle helpers are now bounded. `ActivateSharedSystemObject`
    (`0xC002C0A8-0xC002C11B`) clears elapsed fields, invokes the object's virtual
    activation hook, records the current shared timing state, updates the shared
    timestamp under interrupt masking, advances the shared sequence counter, and
    sets object byte `+0x28`. `DeactivateSharedSystemObject`
    (`0xC002C12C-0xC002C137`) clears that active byte. These lifecycle operations
    are confirmed; the product-level meanings of the selected objects remain
    unresolved.
  - The selected object addresses are now resolved. `g_voiceTaskSharedSystemObjectMode23`
    at `0xC03402B8` is activated for selectors 2 and 3; it is constructed by
    `ConstructSharedSystemObjectMode23` (`0xC002B494-0xC002B4D3`) and its static
    initializer is `InitializeSharedSystemObjectMode23` (`0xC002B4DC-0xC002B4FF`),
    registered at `0xC00F88E0`. `g_voiceTaskSharedSystemObjectMode4` at
    `0xC0340310` is activated for selector 4; its corresponding constructor and
    initializer are `ConstructSharedSystemObjectMode4` (`0xC002B628-0xC002B667`)
    and `InitializeSharedSystemObjectMode4` (`0xC002B6B8-0xC002B6DB`), registered
    at `0xC00F88E4`. The distinct vtables and initialization constants are
    confirmed; product-level object names remain unresolved.
  - The two object vtables expose distinct rate-history implementations. The mode-2/3 object keeps
    eight samples at `+0x30..+0x4C`, averages them in 100-unit steps, and throttles refreshes with
    `+0x54` through `InitializeSharedSystemObjectMode23RateState`
    (`0xC002B380-0xC002B3AF`) and `ApplySharedSystemObjectMode23RateSample`
    (`0xC002B3E0-0xC002B493`). The mode-4 object keeps four samples at `+0x30..+0x3C`, uses
    countdown `+0x44`, and exposes the corresponding `InitializeSharedSystemObjectMode4RateState`
    (`0xC002B530-0xC002B557`) and `ApplySharedSystemObjectMode4RateSample`
    (`0xC002B57C-0xC002B627`) paths. Both tail-dispatch the common VoiceTask rate refresh.
  - The static vtables are now labeled `g_vtSharedSystemObjectMode23`
    (`0xC00A45F8`) and `g_vtSharedSystemObjectMode4` (`0xC00A4618`): their
    `+0x08` slots share the elapsed updater, while `+0x0C/+0x10` select the
    mode-specific adjustment/state and rate-sample operations documented above.
  - The timer-expiry support around these objects is also bounded. `AdvanceSharedSystemObjectElapsed`
    (`0xC002C018-0xC002C043`) conditionally adds the record increment pair at `+0x20/+0x24` to
    the elapsed pair at `+0x18/+0x1C`. `CheckSharedSystemObjectSequenceGate`
    (`0xC002C138-0xC002C157`) compares the shared counter against record field `+0x2C`, while
    `AdjustSharedSystemObjectSequence` (`0xC002B8C0-0xC002B8EF`) changes the shared counter under
    interrupt masking. The counter units and product-level timing meaning remain unresolved.
  - `VoiceTask::taskProc` calls `InitializeVoiceTaskRuntimeState` (`0xC0057884`)
   during runtime setup. That initializer chains the SeqTask position-state reset,
  16-part VoiceTask slot-state initialization, four-word SeqTask PRNG seeding,
  mapped-state construction, and VoiceTask DSP/control construction. The mapped
   state is a separate lazily allocated `0xBAC`-byte object published through
   `g_pVoiceTaskMappedStateObject` (`0xC068D8E0`); its reset/set and special-state
   consumers are confirmed, but its internal field meanings remain unresolved.
 - `ResetVoiceTaskSlotAndMappedState` (`0xC0057848-0xC005786B`) is called by the
   LCD/panel reset path. It raises `g_bVoiceTaskTransportGate` (`0xC068D060`),
   enters SeqTask transport state `1`, clears VoiceTask slot records, and resets
   the mode-4 mapped-state values for all 16 indices. `GetVoiceTaskTransportGate`
   (`0xC0057870`) exposes that gate; SeqTask cycle processing and several VoiceTask
   slot-event paths suppress normal work while it is set.
- The 32-record array is used as 16 primary/paired slots. `GetActiveSeqRecordWord`
  (`0xC005E3BC`) checks the paired slot at index `i + 0x10` before the primary
  slot `i`, using each record's `+0x24` byte as an active flag, and returns the
  active record's first word. `UpdateSeqRecordSelection` (`0xC005E41C`) caches
  the selected index at `0xC0690DC3`, updates the selected value at
  `0xC0690DC0`, toggles state through `0xC00582F0`, and dispatches the selected
  high-part value through `0xC005E400`.
- The `0xC005E400` boundary was corrected. `SetSharedStateField32C`
  (`0xC005E400-0xC005E418`) rejects negative values, obtains the shared state
  object through `0xC00431F0`, and tail-dispatches to the separately defined
  `SetStateObjectField32C` (`0xC0081960-0xC0081998`). Confirmed callers include
  SeqTask record-selection and timing paths. The latter updates the object's
  `+0x32C` field only when changed and emits internal event code `4` through
  `0xC0070688`; the higher-level field meaning remains unresolved.
- The sequencer/voice state path contains another family of mapped-state helpers.
  `SetMappedStateValue` (`0xC00582F0-0xC0058308`) normalizes a boolean value,
  obtains the shared object through `0xC068D8E0`, and tail-dispatches to
  `UpdateMode4MappedState` (`0xC0088CF0-0xC0088DC8`). The latter is active only
  when the object field at `+0xB58` is `4`, maps the caller index through the
  table at `0xC00E5057`, updates a `+0x09` record flag, refreshes the mapped
  record, and may emit a five-byte state record. `ResetMappedStateEntries`
  (`0xC00582C0-0xC00582E8`) applies the zero value across all 16 entries.
- The mapped-state object constructor is `InitializeVoiceTaskMappedStateObjectData`
  (`0xC0087BE8`), which initializes the `0xBAC`-byte object and installs vtable
  `0xC00E5110`. Confirmed object fields include the mode gate at `+0xB58`, current
  mapped index at `+0xB60`, suppression/refresh gates at `+0xB98` and `+0xBA5`,
  outgoing fields at `+0xB4C..+0xB4E`, and per-entry copied payloads rooted at
  `+0x88C`. `PublishMappedStateRecord` (`0xC00875F4`) copies an entry payload,
  updates those outgoing fields, and emits the five-byte panel-UART0 record
  `{0x00, mapped-index, mapped-state, 0x00, 0x00}` when the publish gate permits
  it. This is a broad mapped-state output stream; the individual panel meanings
  of the mapped indices remain unresolved.
  `SetMappedStateEntryAndPublish` (`0xC0087710-0xC008773F`) is the generic per-entry
  updater used by the service paths; it writes the entry boolean/flag fields and an
  associated halfword before publishing. `SetMappedStateRecord0BAndPublish`
  (`0xC0087FD8-0xC0087FFB`) and `SetMappedStateRecord1DAndPublish`
  (`0xC0088170-0xC0088187`) update separate mapped-state fields and emit record
  subtypes `0x0B` and `0x1D` respectively. `ApplyMappedStateProfileGroup`
  (`0xC00877D8-0xC008788B`) and `ApplyMappedStateThreeEntrySelection`
  (`0xC0088118-0xC0088167`) publish fixed-size mapped-entry groups. These are
  confirmed data-flow roles; product-level field meanings remain unresolved.
  `InitializeMappedStateEntriesAndPublish` (`0xC00876AC-0xC008770F`) is the shared
  88-entry initializer used by the service state machines. It assigns indices, writes
  the observed default entry values (including halfword `3`), copies each payload, and
  publishes every entry with type `1`.
  `AdvanceMappedStateEntryTimers` (`0xC0087740-0xC00877D7`) advances the per-entry
  timer at `+0x52` for modes `2` and `3`, toggling or clearing the entry state on
  expiration. The four-entry helpers `ApplyMappedStateProfileMode`
  (`0xC0087914-0xC0087A97`), `ApplyMappedStateFourEntryTableB6C`
  (`0xC0087A9C-0xC0087AF3`), `ApplyMappedStateFourEntryTableB7C`
  (`0xC0087AFC-0xC0087B53`), and `ApplyMappedStateFourEntryTableB68`
  (`0xC0087B5C-0xC0087BAB`) update fixed entry groups from their associated tables.
  `RefreshMappedStateSelectedEntryFlags` (`0xC0087F0C-0xC0087F77`) rebuilds the
  sixteen-entry selection table, while `UpdateMappedStateDerivedPair`
  (`0xC0088220-0xC0088277`) performs the fixed-point transform feeding the derived
  twelve-entry group.
  `ResetMappedStateAuxiliaryRecords` (`0xC00885E4-0xC008868F`) clears auxiliary
  fields and publishes subtypes `0x0C–0x11` plus `0x14`, then raises the `+0xBA4`
  refresh gate. `RefreshMappedStateTimingFields` (`0xC0088690-0xC0088703`)
  refreshes mapped-state timing fields `+0xB9C/+0xBA0` from the shared context.
  `SetMappedStateRecord10AndPublish` (`0xC0088188-0xC00881A3`) emits subtype `0x10`

  `SetMappedStateRecord0FAndPublish` (`0xC008925C-0xC0089267`) emits subtype `0x0F`
  from the descriptor-state result stored at `+0xC6`.
  `RefreshVoiceTaskMappedStateEntriesByMode` (`0xC0088ECC-0xC00890D7`) is the central
